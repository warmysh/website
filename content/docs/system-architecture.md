# Архитектура системы

Этот документ отвечает на вопрос: **как распределена ответственность между слоями и почему интерфейс/сеть не могут обойти контур безопасности**.

## Слоистая модель

Система разделена на уровни:

- интерфейс (UI/WebUI);
- ядро управления;
- контур безопасности;
- силовой ввод/вывод.

Слои не обходят нижележащие проверки.

## Поток команд к нагреву

Команда проходит путь:

Интерфейс -> Ядро -> Проверка безопасности -> Силовая часть

При нарушении условий безопасности команда не исполняется.

## Изоляция интерфейса и сети

- Интерфейс не управляет силовой частью напрямую.
- Интерфейс не имеет доступа к аппаратным размыкателям.
- Сетевые сервисы (HTTP) не содержат команд запуска нагрева и используются для мониторинга/диагностики/настройки.
- Доступ к локальному WebUI защищён PIN-кодом; авторизованный WebUI может штатно завершить программный обжиг (с подтверждением).

## Роль контура безопасности

- Контур безопасности имеет приоритет над остальными слоями.
- Контур может запретить нагрев при обнаружении нарушений.
- Контур не зависит от интерфейса и сетевых сервисов.

## Состояния автомата

- IDLE — ожидание, нагрев запрещён.
- RUN — выполнение программы, включая сегменты снижения температуры по заданной скорости.
- COOL — пассивное остывание после завершения программы.
- ABORT — аварийная остановка.

Переходы валидируются по фиксированным правилам.
Восстановление после сбоя питания — процедура поверх безопасного состояния ожидания
(с проверкой условий продолжения), а не отдельное состояние автомата.

## Продолжение программы после сбоя питания

Условия продолжения программы и поведение после аварий определены в документе [Концепция безопасности](/docs/safety-concept/).

## Архитектурные ограничения

- Запуск нагрева возможен только локально (с физической панели).
- Удалённый запуск нагрева через сеть не реализован.
- Остановка программного обжига дополнительно доступна из авторизованного локального WebUI; из облака управление нагревом невозможно.
- Безопасность не делегируется интерфейсам и сети.

Подробности реализации и параметры настройки предоставляются партнёрам отдельно.
