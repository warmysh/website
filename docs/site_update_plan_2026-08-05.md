## P0 — Критичные неточности (сайт описывает поведение мягче, чем реализовано)

Сайт сейчас обещает «предупреждение, нагрев продолжается» там, где прошивка делает ABORT. Это худший тип ошибки для сайта, который декларирует «честные формулировки».

| № | На сайте | В прошивке (v1.2) | Файлы сайта |
|---|---|---|---|
| 1 | «Нет ожидаемого роста температуры» — предупреждение | `TEMP_NOT_RISING` (<5 °C за 20 мин нагрева) — **ABORT** | `safety.md`, `docs/failure-modes.md` |
| 2 | «Перегрев холодного спая» — предупреждение | ≥50 °C — warning, **≥65 °C в течение 15 с — ABORT** | `safety.md`, `docs/failure-modes.md` |
| 3 | «Потеря канала тока в RUN» — предупреждение, нагрев продолжается | warning ~2 с, **непрерывная потеря ~7 с — ABORT** | `safety.md`, `docs/failure-modes.md` |
| 4 | Отсутствуют новые защиты | Ток >20 А → ABORT; ток >0,10 А при OFF >3 с → ABORT; `TEMP_DROPPING` (>30 °C за 2 мин) → ABORT; sensor stuck (<0,5 °C за 16 с при duty ≥20 %) → ABORT; деградация <85 % — warning, <60 % — ABORT | `safety.md`, `docs/failure-modes.md`, `docs/technical-specification.md` |
| 5 | Второй размыкатель — «контактор» | Реле K1 `SLA-05VDC-SL-A`; канон v1.2 §3.1 прямо запрещает называть его контактором / независимой safety-защитой | `index.md`, `safety.md`, `docs/failure-modes.md`, `docs/technical-specification.md` |
| 6 | «Запуск и остановка нагрева — только с физической панели» | Остановка штатно доступна из авторизованного локального WebUI (AP/STA, с подтверждением). Запуск — по-прежнему только с панели | `docs/cloud-monitoring.md` |
| 7 | Не упомянуто, что холодный SELFTEST реально включает K1+SSR на 100 % до 9 секунд | Эксплуатационное предупреждение из паспорта v1.2 §5 | `docs/selftest-scope.md` |

Источники: `docs/DATASHIT_AND_INSTRUCTION/Техническое_описание_и_инструкция_по_интеграции_v1.2.md` §3.1, §6; `pasport_v1.2.md` §5; `Руководство_по_эксплуатации_v1.2.md` §8.1.

## P1 — Устаревшие факты и версии

1. **Версии.** Сайт: «Docs v0.1», «Реализация: v0». Проект: продуктовая документация **v1.2** (ACTIVE CANON), прошивка **1.1.3**, WebUI **1.3**, OTA-релизы 1.0.6→1.0.8 (live). ⚠️ Внутри проекта README заявляет «платформа v1.5.3» — перед правкой выбрать каноническую нумерацию для сайта (v1.2-доки объявлены каноном, README «вторичен»).
2. **PIN-доступ к WebUI** — на сайте WebUI без аутентификации. Реализовано: 4-значный PIN на весь WebUI/API, 5 попыток → блокировка 60 с, cookie до 7 суток, смена PIN сбрасывает сеансы. Править: `platform.md`, `oem.md`, `docs/technical-specification.md`, `docs/integration-checklist.md`.
3. **AP mode v1.1** — на сайте AP только «режим настройки». Реализовано: полный WebUI через AP, включая RUN; перенастройка Wi-Fi во время обжига (применение — после конца RUN). Править: `roadmap.md`, `platform.md`.
4. **OTA** — на сайте только «в IDLE, вручную, подпись манифеста». Добавить: фоновая read-only проверка манифеста (IDLE ≥10 мин, ≤1 раз/24 ч, без автоустановки), канал `critical`, ручной откат на предыдущий A/B-слот из сервис-меню, лестница восстановления HTTPS → HTTP-люк (Ed25519 не зависит от транспорта) → USB. Править: `index.md`, `oem.md`, `docs/technical-specification.md`.
5. **Семантика состояний** — на сайте COOL = «контролируемое остывание». Зафиксировано иначе: RUN включает контролируемое (PID) охлаждение; COOL — пассивный пост-программный простой. Появилось состояние RECOVERY. Править: `platform.md`, `docs/system-architecture.md`, `docs/technical-specification.md`.
6. **Resume-параметры** — на сайте «интервал задаётся конфигурацией». Конкретика: перерыв до 300 с; точное продолжение при Δ≤5 °C; Δ>50 °C — только вручную. Править: `docs/safety-concept.md`, `safety.md`.
7. **Облачные уведомления** — на сайте только email. Реализовано: email + Web Push + центр уведомлений; новые события: достижение температуры (temp_reached, 1–1300 °C), отклонение от уставки, износ термопары; заметки к обжигу (Burn Note); энергия обжига (кВт·ч) и CSV-экспорт. Править: `docs/cloud-monitoring.md`.
8. **Привязка/отвязка печи** — добавить параметры claim-кода (8 символов, 24 ч, одноразовый, повтор ≤1 раз/5 мин) и штатную отвязку («Настройки печи → Отвязать печь»). Править: `docs/cloud-monitoring.md`.
9. **Watchdog и I_ref** — конкретизировать: TaskWDT 5 с; `I_ref_unit ∈ [0.70…1.15] × I_nominal`, «калибровка не может изменить класс печи». Править: `docs/technical-specification.md`.

## P2 — Roadmap сайта устарел

1. **Многозонность (2–3 зоны) «в разработке»** — в актуальных планах проекта (roadmap.md, PROFORGE_V2.md) многозонность не фигурирует вообще. Убрать или осознанно оставить — нужно решение владельца. Файлы: `index.md`, `configurations.md`, `roadmap.md`.
2. **«MQTT — v1.1+»** — MQTT DE-SCOPED из v1 и в v2-планах отсутствует. Снять формулировку «запланирован». Файлы: `roadmap.md`, `docs/technical-specification.md`.
3. **Перенести реализованное из «планов» в «сделано»**: PIN, полный WebUI через AP, фоновая проверка OTA, ресурс термопары (tc_life), «Ресурс спирали», Web Push.
4. **Отразить реальный v2-план**: обжиг по конусам, второй температурный канал, Logs Server v2 (PostgreSQL), аналитика качества обжига (overshoot, settling, SSR duty), web-портал диагностики, TFT-редизайн, плата v3, образ восстановления, 6-значный PIN.

## P3 — Новые разделы (контент уже готов в проекте)

1. **Раздел «Руководства»** — выложить продуктовый пакет v1.2: паспорт, руководство по эксплуатации, быстрый старт, тех.описание и инструкция по интеграции (`docs/DATASHIT_AND_INSTRUCTION/`). Проектный roadmap прямо описывает proforge.ru как «controller-first landing + Руководства».
2. **Страница модели TERRA-1150** — первая именованная серийная конфигурация: 1150 °C уставка / 1250 °C hard cutoff / 220 В / 1386 Вт / 6,3 А; ESP32-S3 N8R8, MAX31856 + Type-K, PZEM-004T + CT 1000:1, TFT 2,4″. Сейчас страница «Конфигурации» абстрактная.
3. **Быстрый старт онлайн** — AP `TERRA-1150-XXXX` → 192.168.4.1 → PIN → Wi-Fi → привязка на app.proforge.ru (ID + код/QR).
4. **Диагностика ресурса** — счётчик наработки термопары с зонами износа + «Ресурс спирали» на экране диагностики. По исследованию (`PROFORGE_SITE_RESEARCH_SUMMARY_V1.md`) бьёт в боли №1 («потеря обжига») и №3 («понятная диагностика»).
5. **Понятные причины аварий** — «что произошло / что сделал контроллер / что проверить» + service code, на экране и в облаке. Прямой ответ на боль «Err 3, Sensor Fault».
6. **История обжигов**: energy_kwh, CSV-экспорт, Burn Notes.
7. **Доказательная база** — сайт декларирует её, но не показывает: 116+52 host-тестов, FMEA-серия Ф1–Ф5 (32 находки), `-Werror`, анти-кирпич аудит, live-верификация OTA E2E.
8. **Для OEM-раздела**: профили материалов спирали (FeCrAl A-1, FeCrAl D/AF, NiCr 80/20, NiCr 60/15), лимиты программ (20 программ × 50 сегментов, 1–550 °C/ч, выдержка до 1440 мин, JSON ≤16 КиБ), сервисное меню (7 пунктов).

## Рекомендация по подаче (из website_research)

Порядок повествования: спокойствие → программа → конструктор → безопасность/восстановление → работа без интернета → понятные аварии → история → облако → уведомления → технические детали. Текущий сайт местами инженерно-центричен (ESP32/PSRAM/watchdog в первых экранах) — при правках смещать акцент на пользовательскую ценность.
